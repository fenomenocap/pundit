# Pundit — Football Prediction Analysis

Chat-first WC 2026 matchup analysis. Ask about a fixture ("France vs Morocco") and get a plain-language read generated by Claude, grounded in precomputed Dixon-Coles/Poisson model probabilities — not invented. No blockchain, no database, no trading. There used to be a full onchain parimutuel trading platform here; it was removed and archived to git tag `archive/onchain-trading-v1` (recoverable via `git checkout` if ever needed, but out of scope for current work).

**Status:** Deployed (Vercel + Railway). The chat feature (`POST /api/ask`) is currently non-functional in production — `ANTHROPIC_API_KEY` is not set on Railway. This is a known, deliberate gap, not a bug to silently work around.

---

## Tech stack

| Layer | Technology |
|---|---|
| Monorepo | pnpm workspaces (Node ≥18, pnpm 9.15.4), 2 packages: `api`, `web` |
| Frontend | Next.js 14 App Router, TypeScript, TailwindCSS, shadcn/ui primitives (`components/ui/`) |
| Backend | Express + TypeScript, `@anthropic-ai/sdk` |
| Data | ESPN public scoreboard/standings API, Polymarket Gamma API, worldcup-model static JSON — all public, no auth |

No Prisma, no Postgres, no wagmi/viem/RainbowKit, no Solidity/Hardhat. Don't reintroduce any of these without discussing it first — the whole point of the last pivot was to drop the trading platform.

## Data sources

| Source | Used by | Notes |
|---|---|---|
| **ESPN scoreboard/standings** (`packages/api/src/services/football-data.ts`) | `/api/matches/*` routes → `/fixtures` page | Public, keyless. Cron refresh every 6h. Returns real fixtures/results/standings with a `stage` field (`group-stage`, `round-of-32`, `round-of-16`, `quarterfinals`, `semifinals`, `3rd-place-match`, `final`). |
| **Polymarket Gamma API** (`packages/api/src/services/polymarket-data.ts`) | `/api/polymarkets/*` routes | Still fetched and cached server-side, cron every 6h — but **no frontend currently consumes it**. The component that used to render this (`polymarket-ticker.tsx`) was removed as dead code; the route/service themselves were kept since they're cheap and could back a future feature. Don't assume this means the route is dead code too. |
| **worldcup-model** (`packages/api/src/services/model-data.ts`) | `/api/model/*` routes, `/model` page (iframe), `/api/ask`'s grounding data | Public static JSON at `worldcup-model.vercel.app`. `/model` page is a **do-not-touch iframe embed** of the external site itself — nothing to fetch/parse there. `/api/ask` reads the same cached fixture data via `getCachedModelData()` (no separate fetch). |
| **Anthropic API** (`packages/api/src/services/ask.ts`) | `POST /api/ask` | Generates the actual chat answer, grounded in a specific fixture's model probabilities. Requires `ANTHROPIC_API_KEY` — currently unset in production, so every call 502s with "ANTHROPIC_API_KEY is not configured." This is expected until someone sets it. |

## Environment variables

```bash
API_PORT=3001
API_URL=http://localhost:3001

# ── Frontend (Next.js) ────────────────────────────────────────────────────────
NEXT_PUBLIC_API_URL=http://localhost:3001

# ── worldcup-model (public, no key needed) ───────────────────────────────────
MODEL_DATA_BASE_URL=https://worldcup-model.vercel.app

# ── Anthropic (required for POST /api/ask) ───────────────────────────────────
ANTHROPIC_API_KEY=
```

## Mock mode

`USE_MOCK = process.env.NEXT_PUBLIC_USE_MOCK !== "false"` (defaults **true**). Gates the three surviving fetch wrappers in `packages/web/src/lib/mock-data.ts` (`fetchUpcomingMatches`, `fetchRecentMatches`, `fetchStandings` — used by the `/fixtures` page). When `true`, returns small hardcoded fixtures instead of hitting the real API.

## Design rules

- Dark theme only, CSS variables in `packages/web/src/app/globals.css` (navy background, cyan/pink accent hues via shadcn's HSL token convention).
- Mobile-first responsive.
- `/model` page: iframe embed of the external worldcup-model site — **do not touch**, per explicit standing instruction. Don't try to re-theme it, re-fetch its data, or replace the iframe with a native reimplementation.

---

## DO NOT

- Reintroduce Prisma/Postgres, wagmi/viem/RainbowKit, or any onchain trading concept without discussing it first.
- Hardcode `ANTHROPIC_API_KEY` or attempt to set it yourself — that's explicitly the user's call, not something to fill in as a "fix."
- Touch `/model`'s iframe embed.
- Assume `/api/polymarkets/*` or `/api/model/*` routes are dead just because no current page renders them — they're intentionally kept (see Data sources above).
- Call `fetch()` raw in page components for matches/standings data — go through `lib/mock-data.ts`'s wrappers, which honour `NEXT_PUBLIC_USE_MOCK`.
