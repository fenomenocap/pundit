# Chat eval runbook

Production chat quality uses a **Schema-17** harness against live API and web deployments. It consumes **OpenRouter credits** — run manually after meaningful deploys, not in CI.

**Target:** the harness (`scripts/chat-battle-test.mjs`) and the daily workflow sweep the production DigitalOcean API by default. Set `PUNDIT_API_URL` to sweep another deployment. The retired Railway service still serves a frozen build, so never point a sweep at it (until 22 Oct 2026 the daily sweep did, so a totals check failed on wording that current code no longer produces).

## Quick commands

| Command | Role |
| --- | --- |
| `pnpm chat-eval:dry-run` | Validate scenario config without traffic |
| `pnpm chat-eval:test` | Unit tests for harness scripts (no production) |
| `pnpm chat-eval:production` | Battle-test → `artifacts/chat-evals/latest-run.json` |
| `pnpm chat-eval:browser` | Playwright JSON against evaluated web origin |
| `pnpm chat-eval:finalize` | Bind browser + critic JSON into certification report |
| `pnpm chat-eval:gate` | Assert pinned monitor gate fixture (CI-safe) |
| `pnpm chat-eval:build-gate-fixture` | Regenerate pinned gate fixture from a passing run |

## Four-step certification (release-grade)

1. **Battle-test** — `pnpm chat-eval:production` with ≥ **13 s** between request starts (Schema 17 enforces spacing, gaps, and timestamps).
2. **Browser JSON** — `pnpm chat-eval:browser` (or `--dry-run` for checklist only).
3. **Agent critic JSON** — human/agent review file with per-turn verdicts (not generated by repo scripts).
4. **Finalize** — `pnpm chat-eval:finalize --browser-json <path> --critic-json <path>`. Release decisions require `overall: "PASS"`.

Optional: **LLM judge** utilities in `scripts/chat-eval-llm-judge.mjs` for secondary quality scoring (OpenRouter key required).

## Deterministic gate (CI)

`pnpm chat-eval:gate` replays **recorded search** fixtures so certification does not depend on live web search variance. Related env: `CHAT_EVAL_SEARCH_REPLAY_DIR`, `CHAT_EVAL_SEARCH_REPLAY_ID`, `WEB_SEARCH_REPLAY_RECORD`.

## Engine comparison

- Default battle-test uses **legacy** engine.
- Set **`CHAT_EVAL_ENGINE=agent`** to evaluate the tool-calling engine.
- With search replay active, **`X-Pundit-Chat-Engine`** header can override per request (eval guard only). See [Chat engine](../how-it-works/chat-engine.md).

### Daily side-by-side (GitHub Actions)

Workflow [`.github/workflows/chat-eval-daily.yml`](../../.github/workflows/chat-eval-daily.yml) runs legacy (gated) and agent (non-gating) sweeps, then **`node scripts/merge-dual-engine-chat-eval.mjs`** to produce a combined `latest-run.json` with `engineQualityComparison`. Flip criteria for production agent mode: [Chat engine rollout readiness](chat-engine-rollout-readiness.md).

## What Schema-17 guards

Non-exhaustive: internal jargon, raw search payloads, incomplete endings, match scoreline arithmetic, table-source fidelity, abstained counterfactuals, team-news sourcing, high-line geometry, clause-scoped certainty, build-floor SHA convergence, deployment id, pacing gates, and critic PASS on every HTTP 200 turn.

Full criteria: [`AGENTS.md`](../../AGENTS.md) § Chat eval cadence.

## Quality metrics

`scripts/chat-eval-quality-metrics.mjs` computes aggregate metrics from run artifacts for dashboards and regressions (used alongside battle-test output).

## Regrade recorded runs

`node scripts/regrade-chat-runtime.mjs --report <path>` re-applies current evaluator helpers to a saved battle-test report without re-hitting production (useful after evaluator script changes).
